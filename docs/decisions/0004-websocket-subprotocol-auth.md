# 0004. WebSocket 인증 토큰은 하위 프로토콜로 받는다

- 상태: 채택

## 맥락
앱(모바일·웹)이 WebSocket 으로 연결할 때 사용자 JWT 를 넘겨야 한다. 브라우저의 WebSocket API 는 생성자에 주소와 하위 프로토콜 목록만 받아서 임의 헤더를 붙일 수 없다.

## 선택지
1. 주소의 쿼리 문자열로 토큰을 보낸다.
2. 연결 뒤 첫 메시지로 토큰을 보낸다.
3. 하위 프로토콜 목록에 `bearer.<JWT>` 를 넣고, 계약 이름 `map.vision.v1` 을 함께 보낸다.

## 결정
3번. 쿼리 문자열은 접근 로그와 프록시 로그에 그대로 남기 쉽다. 첫 메시지 방식은 인증 전에 연결을 수락해야 한다. 하위 프로토콜은 수락 전에 확인할 수 있고, 서버는 응답에 `map.vision.v1` 만 실어 토큰을 되돌려 보내지 않는다.

## 결과
- 인증에 실패한 연결은 수락하지 않는다. 브라우저에서는 이유가 보이지 않으므로, 앱이 거절 뒤에 동의 상태를 다시 확인한다.
- `map.vision.v1` 의 `v1` 은 API 경로의 `/v1/` 과 같은 계약 판이다. 메시지 계약을 깨는 변경에만 올린다.
