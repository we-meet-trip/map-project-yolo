# 0003. 권한과 계정 한도는 User BFF 가 갖고, 이 서비스는 작업마다 세 번 묻는다

- 상태: 채택

## 맥락
인식 한 번마다 유료 외부 모델을 부른다. 로그인 상태, 연령·정책 동의, 외부 AI 전송 동의, 계정별 하루 한도가 모두 User 서비스(BFF)에 있다. 이 서비스는 데이터베이스가 없다.

## 선택지
1. 이 서비스가 JWT 를 직접 검증하고 한도를 따로 센다.
2. 연결할 때만 User BFF 에 묻는다.
3. User BFF 의 허가 API 를 연결 때, 처리 직전, 전송 직전에 부른다.

## 결정
3번. 연결 때는 `consume=false` 로 확인만 하고, 처리 직전에 `consume=true` 로 한도 1을 쓰고, 전송 직전에 다시 `consume=false` 로 확인한다. 연결 때의 사용자 ID 와 동의 개정 번호를 소켓에 고정하고, 뒤 호출에 `expected_revision` 으로 보낸다. 서비스 간 호출에는 전용 내부 토큰(`MAP_PROJECT_VISION_INTERNAL_TOKEN`)을 쓴다.

## 결과
- 계정 한도는 재접속으로 초기화되지 않는다. 한도·동의 규칙을 바꿀 때 이 서비스를 고치지 않아도 된다.
- 작업 하나에 허가 호출이 세 번 생긴다(같은 배포 안의 짧은 호출).
- 허가 서비스가 죽으면 모든 연결이 닫힌다(`1013`). 권한을 확인할 수 없으면 외부 모델을 부르지 않는 쪽을 골랐다.
