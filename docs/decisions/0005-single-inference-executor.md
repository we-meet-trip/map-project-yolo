# 0005. 추론은 전용 실행기 하나에서만 돌리고, 넘치면 기다리게 하지 않고 거절한다

- 상태: 채택

## 맥락
YOLO 모델은 프로세스에 하나만 올리고 CPU 로 돈다. native 추론은 비동기 제한시간으로 취소되지 않는다.

## 선택지
1. 요청마다 스레드 풀에 맡기고 큐에 쌓는다.
2. 전용 스레드 하나에서만 추론하고, 앞선 추론이 끝나지 않았으면 새 사진 요청을 바로 거절한다.

## 결정
2번. 프로세스 전체 동시 작업 상한(`YOLO_MAX_CONCURRENT_JOBS`, 기본 2)과 사진 작업 하나를 따로 센다. 자원을 못 잡으면 계정 한도를 쓰기 전에 "처리 중" 응답을 보낸다.

## 결과
- 제한시간이 지난 추론이 남아 있어도 같은 모델을 겹쳐 부르지 않는다. 큐가 쌓여 지연이 늘어나는 일도 없다.
- 동시에 몰리면 일부 사용자는 다시 시도해야 한다. 처리량을 늘리려면 프로세스(컨테이너)를 늘린다.
- 멈춘 native 추론을 강제로 끝낼 수는 없다. 그때는 프로세스를 다시 띄운다.
