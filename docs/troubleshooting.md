# 트러블슈팅과 교훈

개발 중에 실제로 겪은 문제와 고친 방법이다. 항목마다 증상, 원인(근거), 해결, 검증, 교훈, 관련 커밋을 적는다. 이미 고친 보안 결함도 코드 수준에서 설명한다.

## 연결·권한

### T-VISION-01 인증 없이 열린 카메라 소켓
- **증상**: `/ws/vision` 이 인증 없이 열려 있었다. 메시지 크기 상한도 없어서, 아무나 연결해 외부 모델 호출을 쓸 수 있었다.
- **원인**: 처음 구현은 앱 안에서만 쓰는 경로로 보고 인증 가드를 두지 않았다.
- **해결**: 사용자 JWT 를 하위 프로토콜 `bearer.<JWT>` 로 받는다. 연결 전과 작업마다 User BFF 허가 API 로 로그인·정책·동의·계정 한도를 확인한다. 메시지·사진·연결·프로세스 단위 상한을 넣었다(`map_project_yolo/api/ws.py`, `map_project_yolo/schemas/vision_schemas.py`, Dockerfile 의 `--ws-max-size`).
- **검증**: `tests/test_vision_security.py` 의 `test_unauthenticated_connections_never_accept_or_call_model`, `test_invalid_request_never_spends_account_quota`, `test_pixel_bomb_is_rejected_before_inference`.
- **교훈**: "앱만 부른다"는 가정은 경로가 관문 밖으로 열리는 순간 깨진다. 외부 비용이 드는 경로는 처음부터 인증과 상한을 둔다.
- **관련 커밋**: {{commit:053a0d0}}

### T-VISION-02 추론 도중 동의·정책이 바뀌어도 결과가 나감
- **증상**: 추론을 시작한 뒤 생년월일 정정, 필수 정책 판 변경, 세션 만료가 일어나도 이미 만든 결과를 그대로 보냈다.
- **원인**: 권한을 추론 전에 한 번만 확인했다.
- **해결**: 결과를 보내기 직전에 허가 API 를 `consume=false` 로 다시 부른다. 거절되면 결과를 버리고 고정된 오류로 닫는다. 계정 한도는 다시 쓰지 않는다.
- **검증**: `tests/test_policy_permit.py` 의 `test_policy_change_while_inference_is_pending_withholds_result`(사진·텍스트 양쪽, 허가 호출 순서 `[false, true, false]`, 한도 1회 사용).
- **교훈**: 오래 걸리는 작업은 시작할 때의 권한이 끝날 때도 유효하다고 가정하지 않는다.
- **관련 커밋**: {{commit:725bfef}}

### T-VISION-03 동의를 철회했다가 다시 하면 예전 소켓이 되살아남
- **증상**: 외부 AI 동의를 철회한 뒤 다시 동의하면, 철회 전에 연 소켓이 그대로 다시 쓰였다.
- **원인**: 소켓이 연결 때의 동의 상태를 기억하지 않아서, 지금 동의돼 있기만 하면 통과했다.
- **해결**: 연결 때의 동의 개정 번호(`consent_revision`)를 소켓에 고정하고, 이후 허가 호출에 `expected_revision` 으로 보낸다. 번호가 다르면 `AI_CONSENT_CHANGED` 로 닫는다.
- **검증**: `test_revoke_then_regrant_never_resumes_original_socket_epoch`, `test_legacy_or_malformed_permission_contract_fails_closed`.
- **교훈**: "지금 허용됨"과 "그때 허용한 것과 같음"은 다르다. 동의처럼 철회될 수 있는 권한은 판 번호로 묶는다.
- **관련 커밋**: {{commit:30277bb}}

### T-VISION-04 거절 사유가 앱에 안 보이거나 상위 오류 문구가 새어 나감
- **증상**: 정책·연령 거절이 모두 같은 오류로 보여 앱이 사용자를 안내할 수 없었다. 반대로 상위 서비스의 오류 본문을 그대로 넘길 위험도 있었다.
- **원인**: 403 본문을 다루는 규칙이 없었다.
- **해결**: 403 의 `code` 는 정해진 다섯 값일 때만 받아들이고, 그 밖의 본문·메시지는 버린다. 사용자 문구는 서비스가 정한 한국어 문장만 쓴다.
- **검증**: `test_only_known_policy_codes_survive_403`, `test_malformed_provider_error_body_is_not_forwarded`, `test_transport_failure_has_fixed_safe_status_and_message`.
- **교훈**: 상위 오류를 전달할 때는 허용 목록으로 걸러 낸다. 차단 목록은 새는 길을 다 막지 못한다.
- **관련 커밋**: {{commit:7ad04f9}}

### T-VISION-05 외부를 한 번도 부르지 않은 연결이 상한에 걸려 끊김
- **증상**: 연결당 처리 상한을 넣자, 형식이 깨진 요청이나 아무 일도 하지 않는 프레임만 보낸 연결이 먼저 끊겼다.
- **원인**: 상한이 받은 프레임 수를 셌다.
- **해결**: 외부를 부르는 처리(텍스트 답변·사진 인식) 직전에만 한 칸씩 쓰게 옮겼다. 상한에 닿으면 사유를 알리고 닫는다.
- **검증**: `tests/test_ws_quota.py` 전체(무시 프레임·형식 오류는 상한을 쓰지 않음, 섞인 흐름에서 외부 호출 횟수만 셈).
- **교훈**: 남용을 막는 장치는 무엇을 세는지 시험으로 고정한다. 잘못 세면 정상 사용자가 먼저 막힌다.
- **관련 커밋**: {{commit:3cda1e4}}

## 인식 파이프라인

### T-VISION-06 대상을 알아내고도 응답이 실패로 나감
- **증상**: 사진 속 대상을 식별했는데도 화면에는 실패가 떴다.
- **원인**: 두 가지였다. 곁들이는 검색이 실패하면 상태에 오류를 세워 응답 전체가 실패가 됐다. 또 전체 제한시간이 식별 제한시간과 같아서, 식별을 마치고도 검색 도중에 잘렸다.
- **해결**: 검색 실패는 빈 결과로 넘기고, 응답 상태는 식별 성공 여부로 정한다. 전체 제한시간(45초)을 식별 제한시간(25초)보다 크게 잡았다.
- **검증**: `tests/test_nodes.py` 의 `test_search_failure_keeps_identify_result`.
- **교훈**: 핵심 결과와 곁들이는 결과의 실패를 같은 무게로 다루지 않는다. 바깥 제한시간은 안쪽 단계의 합보다 크게 잡는다.
- **관련 커밋**: {{commit:5d4c5d8}}

### T-VISION-07 제한시간이 지난 뒤에도 모델 추론이 겹쳐 돎
- **증상**: 응답 제한시간이 지나 실패를 보낸 뒤에도, 다음 요청이 같은 모델로 추론을 또 시작해 CPU 를 겹쳐 썼다.
- **원인**: native 추론은 비동기 제한시간으로 취소되지 않는다. 대기만 끝나고 스레드는 계속 돈다.
- **해결**: 공유 모델은 스레드 하나짜리 전용 실행기에서만 돌린다. 앞선 추론이 끝나지 않았으면 새 사진 요청을 큐에 쌓지 않고 바로 거절한다. 자원을 못 잡으면 계정 한도를 쓰기 전에 거절한다.
- **검증**: `test_native_inference_timeout_does_not_allow_overlapping_model_calls`, `test_pipeline_budget_rejects_extra_jobs_without_queueing`, `test_busy_inference_does_not_spend_quota`.
- **교훈**: 취소할 수 없는 작업에는 제한시간이 "기다림의 끝"일 뿐이다. 실제 실행이 끝났는지 따로 추적한다.
- **관련 커밋**: {{commit:053a0d0}}

### T-VISION-08 좌표 0.0 이 위치 없음으로 처리됨
- **증상**: 위도나 경도가 0 인 위치가 "위치 없음"으로 처리됐다.
- **원인**: `if lat and lng:` 처럼 참거짓으로 판정했다.
- **해결**: `None` 인지로 판정한다(`map_project_yolo/nodes/kakao_local.py`).
- **검증**: 코드 대조. 지금은 위치 스키마가 대한민국 범위만 받지만, 함수는 범위와 무관하게 맞게 판정한다.
- **교훈**: 숫자 0 이 유효한 값이면 참거짓 판정을 쓰지 않는다.
- **관련 커밋**: {{commit:8599aa4}}

### T-VISION-09 모델 기본 판을 쓸 수 없게 될 위험
- **증상**: 코드와 예시 설정의 기본 모델이 폐기 예정 판이었다. 폐기되면 식별과 텍스트 답변이 통째로 멈춘다.
- **원인**: 모델 판을 기본값으로 고정해 두고, 공급자의 판 수명을 추적하지 않았다.
- **해결**: 기본값을 폐기 일정이 발표되지 않은 판으로 옮겼다. 모델 이름은 설정(`MAP_PROJECT_GEMINI_MODEL`)으로 바꿀 수 있다. 결정 기록은 [decisions/0007-gemini-model-default.md](decisions/0007-gemini-model-default.md).
- **검증**: 코드 기본값과 `.env.example` 이 같은 판인지 대조했다.
- **교훈**: 판을 고정한 외부 모델은 공급자 사정으로 갑자기 못 쓰게 될 수 있다. 이미지를 다시 빌드하지 않고 설정만으로 바꿀 수 있게 둔다.
- **관련 커밋**: {{commit:1d947c6}}

## 로그·관측

### T-VISION-10 애플리케이션 로그가 하나도 안 나옴
- **증상**: 어떤 연결이 무엇을 인식했고 무엇이 실패했는지 로그에 보이지 않았다. 경고만 시각·로거 이름 없이 가끔 나왔다.
- **원인**: uvicorn 은 자기 로거만 설정하고 루트 로거에는 핸들러를 붙이지 않는다. 그래서 패키지 로거의 기록은 출력 대상을 찾지 못했다.
- **해결**: 부팅 첫 단계에서 루트 핸들러가 비어 있을 때만 stdout 핸들러를 붙인다. 이미 핸들러가 있으면(테스트 하니스, `--log-config`) 건드리지 않는다. 로그 레벨은 설정으로 바꾼다.
- **검증**: 코드 대조(`map_project_yolo/main.py` 의 `_configure_logging`). 핸들러가 이미 있을 때 중복 출력하지 않는다.
- **교훈**: 프레임워크가 로깅을 "설정해 준다"는 범위를 확인한다. 보통 자기 로거까지만이다.
- **관련 커밋**: {{commit:134560d}}

### T-VISION-11 기기 좌표가 요청 로그에 쌓임
- **증상**: 장소 검색과 역지오코딩을 할 때마다 기기 좌표가 로그 한 줄씩 남았다.
- **원인**: 외부 요청 로거(httpx)가 요청 URL 을 통째로 찍는데, Kakao API 는 좌표를 쿼리(`x`, `y`)로 받는다. 게다가 URL 이 문자열이 아니라 객체 인자로 넘어와서, 문자열만 훑는 필터는 그냥 지나쳤다.
- **해결**: 로그로 나가는 길목(요청 로거, httpx 로거, 루트 핸들러)에 좌표 가림 필터를 건다. 문자열 인자를 가린 뒤 문장을 만들어 보고, 그래도 좌표가 남으면 문장을 미리 조립해 통째로 가린다. Gemini 프롬프트에 넣는 좌표는 소수 셋째 자리로 줄인다.
- **검증**: `tests/test_coordinate_redaction.py`(실제 핸들러를 돌려 로그 전체에 좌표 없음, 가림을 빼면 같은 패턴에 걸리는 대조군, 객체 인자 경로).
- **교훈**: 민감한 값은 만드는 자리가 아니라 나가는 길목에서 막는다. 가림 시험에는 "가림을 빼면 실패하는" 대조군을 함께 둔다.
- **관련 커밋**: {{commit:a5e098c}}

### T-VISION-12 프레임워크 보안 업그레이드 뒤 지표 계약이 깨질 위험
- **증상**: FastAPI·Starlette 를 보안 수정 판으로 올리면 `/metrics` 수집 형식이 바뀔 수 있었다.
- **원인**: 지표 노출을 검사하는 시험이 없었다.
- **해결**: 상태 확인 경로가 지표에 잡히고, 없는 경로는 지표 이름을 만들지 않는다는 계약 시험을 넣었다.
- **검증**: `tests/test_metrics_contract.py`.
- **교훈**: 의존성을 올릴 때 깨질 수 있는 바깥 계약은 업그레이드 전에 시험으로 고정한다.
- **관련 커밋**: {{commit:6d80fa6}}

### T-VISION-13 `curl` 로 WebSocket 경로를 확인하면 404
- **증상**: `curl` 로 `/ws/vision` 을 확인하면 `{"detail":"Not Found"}` 404 가 나와서, 경로가 없다고 잘못 판단하기 쉽다.
- **원인**: 요즘 `curl` 은 HTTPS 에서 HTTP/2 를 먼저 쓴다. HTTP/2 는 WebSocket 업그레이드 헤더를 쓰지 않고, Starlette 의 WebSocket 경로는 WebSocket 요청에만 맞는다.
- **해결**: `curl --http1.1` 로 업그레이드 요청을 보낸다. 토큰이 없으면 수락 전에 닫히고, 유효한 토큰이면 101 이 온다.
- **검증**: 수동 확인. 자동 시험은 `test_real_asgi_websocket_negotiates_protocol_and_echoes_request_id` 가 실제 ASGI WebSocket 으로 협상을 확인한다.
- **교훈**: 상태 점검 도구의 기본 동작(프로토콜 판)이 결과를 바꿀 수 있다. 404 를 보면 요청 방식부터 의심한다.
- **관련 커밋**: 없음(운영 점검 중 확인)

## 빌드·의존성

### T-VISION-14 이미지에 CUDA 판 torch 가 들어가 크기가 커짐
- **증상**: CPU 로만 돌리는 이미지인데 수 GB 짜리 CUDA 판 torch 가 들어갈 수 있었다.
- **원인**: CPU 인덱스를 추가 인덱스로만 주면, pip 이 PyPI 의 더 높은 CUDA 판을 고를 수 있다.
- **해결**: CPU 인덱스에서 torch·torchvision 을 먼저 설치하고, 그 판을 제약 파일로 고정한 뒤 나머지를 설치한다. CI 도 같은 순서다.
- **검증**: 이미지 빌드 마지막의 `scripts/verify-headless-runtime.py` 가 `torch.version.cuda is None` 을 확인한다.
- **교훈**: 여러 인덱스를 섞으면 "가장 높은 판"이 이긴다. 원하는 판은 먼저 고르고 제약으로 묶는다.
- **관련 커밋**: {{commit:053a0d0}}

### T-VISION-15 GUI 판 OpenCV 때문에 런타임에 GUI 라이브러리가 필요해짐
- **증상**: ultralytics 가 GUI 판 OpenCV 를 함께 끌고 와서, 서버 이미지에 GUI·GLib 계열 시스템 라이브러리를 깔아야 했다.
- **원인**: 기본 `ultralytics` 배포판은 GUI 판 OpenCV 에 의존한다.
- **해결**: headless 배포판(`ultralytics-opencv-headless`)으로 바꾸고 시스템 라이브러리를 뺐다. 실행에 필요 없는 perl 과 setuid·setgid 비트도 없앴다. 빌드 때 네트워크를 끈 채 설치 패키지, GUI 라이브러리 부재, 합성 JPEG 추론을 검사한다.
- **검증**: `scripts/verify-headless-runtime.py`, `.github/workflows/runtime-image-audit.yml`.
- **교훈**: 서버용 이미지는 "무엇을 뺐는지"를 빌드 단계의 검사로 남긴다. 그래야 다음 업그레이드에서 다시 들어와도 알아챈다.

### T-VISION-16 기동할 때마다 ultralytics 설정 경고
- **증상**: 비루트 사용자로 띄우면 기동할 때마다 설정 위치 경고가 나고, 설정을 `/tmp` 에 다시 만들었다.

- **해결**: 이미지에서 실행 사용자의 `~/.config` 를 미리 만들어 둔다.
- **검증**: 코드 대조(Dockerfile 의 사용자 생성 단계).
- **교훈**: 비루트 실행으로 바꿀 때는 라이브러리가 쓰는 홈 아래 경로를 점검한다.
